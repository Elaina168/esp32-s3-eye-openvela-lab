# CP3 采集缓冲与显示传输对照

## 条件和计时口径

ESP32-S3-EYE 使用 CP2 修复后的摄像头驱动。摄像头输出 320×240 RGB565，LCD 使用 240×240 居中画面、板级 40 MHz SPI 配置。每组预热 2 秒，再测至少 12 秒。两个测试镜像使用相同的任务 CPU 计时配置，任务运行时间按板级 240 MHz 时钟换算。表中的 CPU 占用是测试任务运行时间占单核墙钟时间的比例，墙钟及帧时间戳的系统节拍为 10 ms。

- 轮询预览按 640 字节步长逐行绘制，直接使用原生 RGB565。
- DMA 预览在应用拥有帧时原地压紧居中的 240×240 像素，整屏提交给 LCD。SPI 驱动用 4,092 字节对齐暂存区分块转换到 SPI 线上的字节顺序，DMA 完成后复用暂存区。纯 DMA 刷屏的固定图在计时前已经压紧。
- 端到端时延从帧结束中断的时间戳计到应用显示调用返回，覆盖取帧、原地裁剪和刷新。它不含摄像头曝光前的等待或屏幕扫描时间。

双缓冲纯采集另外取得 181 个有效帧、0 个错误帧，帧率为 15.021 FPS，帧结束到应用取帧的 P95 为 20 ms。组合方案复跑 45.030 秒，取得 674 个有效帧、0 个错误帧，计 14.968 FPS。固定四色图的 DMA 扩展测试持续 28 秒，提交 962 帧。

正式合并镜像已烧录并进入 NSH，`/dev/lcd0` 存在，`camera 1` 在 15.470 秒后返回并在临时 RAM 盘生成一张 153,600 字节的 RGB 图像。镜像开启 SPI DMA，应用缓冲设为 2，测试用 CPU 计时配置已移除。本轮 DMA 画面的实物颜色与方向未获目视确认，后续优化版补做了实物验证。

## 改动与取舍

**A 采集缓冲。** ESP32-S3-EYE 将摄像头应用的 RING 队列设为两个缓冲。应用图像缓冲少 153,600 字节（150 KiB），同一预览测试进程的共享堆占用增量从 664,104 字节降到 509,952 字节。四组预览结果均接近 15 FPS。缓冲减少后留给慢消费者的排队余量也减少，组合负载的覆盖放在后续回归。

**B SPI DMA。** EYE 启用 SPI DMA。ESP32-S3 的 16 位仅发送路径把原生像素逐块转为 SPI 线上高字节在前的顺序，并通过内部对齐暂存区发出。其他 SPI 传输继续走现有条件判断。主机验证了红、绿、蓝、白四个 RGB565 码值的转换，以及全屏居中裁剪计算。纯刷屏时间降低约 10.8%，任务 CPU 占用降 79.67 个百分点。双缓冲组合相较双缓冲轮询预览的 CPU 占用降 24.09 个百分点，含裁剪的显示步骤和端到端 P95 增加约一个 10 ms 节拍。DMA 方案为每个启用的 SPI 实例增加 4,092 字节静态暂存空间，另有原 SPI DMA 描述符及控制开销。

## 复现

正式构建从锁定源码应用完整补丁，保留 CP2 的 VSYNC、EOF 与边界修复。专项测试将摄像头示例入口临时替换为配套测试源，使用 8 KiB 任务栈。两个镜像启用相同的 `SCHED_CRITMONITOR`、`ARCH_PERF_EVENTS` 和线程计时配置，轮询镜像关闭 SPI DMA，DMA 镜像使用项目记录的 SPI DMA 参数。NSH 测试例为 `camera lcd 12`、`camera capture 12 2`、`camera preview 12 3` 和 `camera preview 12 2`。两种构建及原始数据随本地归档保留。

正式固件 SHA-256 为 `bca5e0180a9cdfb67b3283db5cd267963144f688ff5cd7181332863dc35c8033`。
