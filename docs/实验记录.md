# 实验过程与验收记录

## 2026-11-20 课程基线启动

| 项目 | 操作与证据 | 结果 |
| --- | --- | --- |
| 开发环境 | Ubuntu 22.04 VMware 客机，2 vCPU、8 GiB 配置内存。验证 USB 直通和 `dialout` 组串口读写权限 | 通过 |
| 板卡连接 | 更换 USB 数据线后，客机 `lsusb` 识别 `303a:1001`，串口设备为 `/dev/ttyACM0` | 通过 |
| 版本核对 | `nuttx`、`apps`、`vendor/espressif` 均匹配课程固定提交，详见[版本记录](../baseline-versions.txt) | 通过 |
| 交叉编译 | 使用 Xtensa GCC 12.2.0、课程板级配置和 `build.sh`，显式将 Xtensa 工具链加入本轮 `PATH`，使用 `-j2` 构建 | 通过 |
| 依赖处理 | GitCode 镜像补齐板卡相关仓库，`build`、`.claude` 取自官方 GitHub。使用课程清单中的 LVGL 等依赖，并应用板级源码自带的 HAL 自旋锁构建补丁 | 完成 |
| 烧录 | 将 1,617,844 字节的 `nuttx.bin` 写入偏移 `0x0`，`esptool 5.6.0` 返回 `Hash of data verified.` | 通过 |
| 真机启动 | 串口进入 `NuttShell (NSH)`，`uname -a` 返回板型 `esp32s3-eye` 和内核提交前缀 `dd92bcf4257` | 通过 |
| 设备节点 | `ls /dev` 返回 `video0`、`lcd0` 和 `audio/` | 通过 |

固件 SHA-256 为 `c592158f2f5a2d425b856df2b59c6803c55dbe02b146045e998efba8de2cdfc7`。

ROM 日志出现 `SHA-256 comparison failed` 后继续启动并进入 NSH。启动日志另有蓝牙 HCI 命令被拒绝。两条现象的原因尚未定位。
