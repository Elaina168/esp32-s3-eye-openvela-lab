# CP3 后续 A/B 优化

## 做了什么

- **A 采集内存**。应用仍使用两个 320×240 RGB565 采集缓冲。驱动原来为 153,600 字节图像加 46,080 字节 DMA 余量。本次将余量改为两个 3,840 字节的描述符，分配从 199,680 降到 161,280 字节，节省 38,400 字节（37.5 KiB）。此前真机观察到帧 EOF 后有一个描述符仍可能被写回，本次保留两个的空间，并继续按第一个有效 EOF 校验帧长。
- **B 显示预览**。EYE 的 ST7789 板级初始化注册带步长的批量发送回调。LCD 可直接接收带 640 字节行步长的源缓冲，从每行取居中的 480 字节，在原有 4,092 字节暂存区内同时完成线上字节序转换与分块发送。应用无需再原地搬整幅画面。DMA 等待失败由这条批量路径返回给 LCD 调用方。

## 真机对照

以第一版 CP3 合并方案作为对照，固定 320×240 RGB565、两个采集缓冲、240×240 LCD 居中画面与 40 MHz SPI。对照镜像、只改 B 的镜像及 A+B 镜像使用相同的 RT Timer 微秒计时和测试任务 CPU 计时配置。采集帧结束中断的时间戳也临时改为同一个微秒时钟，正式固件恢复原时钟口径。

| 指标 | 第一版 CP3 | 只改 B | 新 A+B |
| --- | ---: | ---: | ---: |
| 预览有效帧率 | 14.917 FPS | 15.034 FPS | 15.030 FPS |
| 原地裁剪／准备显示参数均值 | 9.643 ms | 0.005 ms | 0.005 ms |
| 裁剪及 LCD 调用合计均值 | 39.694 ms | 29.934 ms | 29.902 ms |
| 帧结束到显示调用返回均值 | 58.556 ms | 48.696 ms | 48.474 ms |
| 帧结束到显示调用返回 P95（1 ms 分桶） | 62 ms | 53 ms | 53 ms |
| 预览测试任务 CPU，占单核 | 25.2% | 10.9% | 10.9% |
| 预览共享堆占用增量 | 509,952 字节 | 509,952 字节 | 471,552 字节 |

纯刷屏平均从 29.009 ms 到 29.048 ms，收益主要体现在带步长的摄像头预览。纯采集关掉 LCD 时，缩小 DMA 余量后仍取到 151 个有效帧、0 个错误帧，帧率为 15.034 FPS。整帧拷贝平均约 12.75 ms，接近原来的 12.76 ms。DMA 内存节省与拷贝耗时分别记录。

## 边界与画面验证

- 主机测试从 320×240 输入取居中像素，核对 115,200 个有效字节按 RGB565 线上顺序拆成 29 个 DMA 分块，并验证传输失败正确返回。缩小余量后以实际描述符构建函数核对常用尺寸和容量上限，分别为 42 和 56 个描述符，链尾均为 `NULL`。
- 缩小余量的真机回归通过 100 次 FIFO 启停，累计 200 帧，并通过短缓冲拒绝、帧后哨兵和 15 秒连续预览检查。
- 组员确认固定四色图正确。首轮目视预览报告疑似花屏，期间串口也出现断连，原因未确定。同一版双缓冲预览重跑 30.044 秒，收到 451 帧、0 个错误帧，组员确认画面完整、没有花屏。

## 正式固件

已烧录并验证进入 NSH，`/dev/lcd0` 存在。`camera 1` 在 15.464 秒后正常返回，在临时 RAM 盘生成 153,600 字节的图像。正式镜像为 1,617,540 字节，SHA-256 为 `fe11e6a340c69c00d2442c1fadb4b1f71ed2ed80f82eedb94b61edf5aad6d5fc`。

三个完整补丁均在锁定版本的干净源文件上通过 `git apply --check`。正式源码与临时微秒计时测试可分别复现。对照镜像和原始日志保存在小组本地。
