# CP2 帧同步修复与复测

## 问题与修复

组员观察到摄像头预览上下分屏、抖动和花屏。LCD 使用同一写入接口显示固定四色图时画面稳定，直接读取的 OV2640 内置色条帧则出现错位。首轮诊断中，GDMA 汇报 177,920–199,680 字节，超过 QVGA RGB565 一帧的 153,600 字节。

修复后，驱动准备好缓冲并等待真实 VSYNC 边沿再启动 CAM/GDMA。诊断确认 DMA 描述符 39（从 0 开始）带 EOF，累计恰好 153,600 字节，之后还可能写回一个 3,840 字节的描述符。驱动现在逐个核对接收长度和描述符容量，在首个 EOF 处结束验证，只交付长度恰好等于预期帧长的图像。

像素字节序复测中，额外交换 RGB565 的两个字节会出现整屏花屏。原始像素中的 `0xf81f` 和 `0xf900` 与色条的洋红、红色相符。预览使用原生 16 位像素交给 LCD 后，组员确认能看到完整画面，动作正常。

[旧版原始色条](assets/cp2/ov2640-before.png) · [修复版原始色条](assets/cp2/ov2640-after.png)。两张图沿用相同的采样与解码方式，用于对照色条几何位置。

## 验证结果

| 项目 | 结果 |
| --- | --- |
| EOF 边界 | 主机 8 项检查通过，涵盖 EOF 后多余数据、短帧、超长、描述符容量不符、DMA 未停稳、缺 EOF 和硬件错误 |
| 原始色条 | 真机连续 20 帧均为 153,600 字节且无错误标志，完整导出的一帧中 60 个采样行保持对齐 |
| 反复启停 | 100 次启停累计交付 200 帧，短缓冲拒绝和帧后哨兵检查通过 |
| LCD 预览 | 组员确认分屏、抖动和花屏消失。最后一条有效计时记录为 450.050 秒、6,734 帧，期间程序未报告错误。30 分钟测试按组员要求提前结束 |
| 正式固件 | 连续两次 `camera 1` 分别在 15.388 秒、15.463 秒返回 NSH，在临时 RAM 盘各保存一张 153,600 字节图像 |

组员另观察到画面偏淡发灰。自动曝光、自动增益和自动白平衡保持开启，色彩准确性尚未使用标准色卡校准。

## 构建与复现

使用锁定清单和现有 [CP2 构建步骤](CP2缺陷修复与复测.md#复现)，从干净源码应用当前 [NuttX 补丁](../patches/cp2/nuttx.patch)。使用更新后的 [cp2-check.c](../tests/cp2-check.c) 构建专项预览镜像。NSH 中执行 `camera 0 100` 复跑启停检查，执行 `camera 1800 100` 可在启停后运行 30 分钟预览。
